# W06 — Day 28: Python `secrets` Module

> Quick reference for generating cryptographically secure random values in Python.

---

## Why `secrets` Exists

The `secrets` module is designed for generating **cryptographically secure random values**.

Use it whenever the generated value protects security, such as:

- Passwords
- Password reset tokens
- API keys
- Session IDs
- URL tokens
- Authentication secrets

---

## Why NOT `random`?

The `random` module uses a **PRNG (Pseudo-Random Number Generator)**.

| Characteristic | Description |
|----------------|-------------|
| Speed | Fast |
| Determinism | Deterministic — predictable if the seed or internal state is known |
| Best for | Games, simulations, animations, non-security tasks |

**Never use `random` for passwords or security tokens.**

```python
import random

random.choice("abcdef")
```

---

## Why `secrets`?

`secrets` uses a **CSPRNG (Cryptographically Secure Pseudo-Random Number Generator)**.

| Characteristic | Description |
|----------------|-------------|
| Source | Uses entropy provided by the Operating System |
| Predictability | Computationally infeasible to predict |
| Best for | Cybersecurity & authentication tasks |

```python
import secrets

secrets.choice("abcdef")
```

---

## PRNG vs. CSPRNG

| Feature | PRNG (`random`) | CSPRNG (`secrets`) |
|---------|-----------------|--------------------|
| Speed | Fast | Slower (but secure) |
| Predictability | Predictable | Extremely difficult to predict |
| Seed | Can be seeded | Uses OS entropy |
| Use case | Games & simulations | Passwords & security |

---

## Entropy

Entropy represents the amount of **unpredictability** in generated random data.

- Higher entropy = harder to guess
- Higher entropy = better security
- Higher entropy = stronger random values

---

## Core Functions

### 1. `secrets.choice(sequence)`

Returns one secure random element from a sequence.

```python
import secrets

alphabet = "abcdefghijklmnopqrstuvwxyz"
letter = secrets.choice(alphabet)
```

> Best for generating passwords character by character.

---

### 2. `secrets.randbelow(n)`

Returns a secure random integer in the range:

```
0 <= number < n
```

```python
secrets.randbelow(100)
```

---

### 3. `secrets.randbits(k)`

Returns a secure random integer with **k random bits**.

```python
secrets.randbits(32)
# Example output: 2847392012
```

> Useful when you need a random integer with a specific bit length (e.g., cryptographic key sizes).

---

### 4. `secrets.token_bytes(n)`

Generates **n random bytes** and returns them as a `bytes` object.

```python
secrets.token_bytes(16)
# Example output: b'\x9f\xa3\x12\x7e...'
```

| Use case | Description |
|----------|-------------|
| Raw binary data | When you need bytes directly (not a string) |
| Cryptographic keys | Feeding into encryption algorithms |
| Custom encoding | When you want to encode bytes yourself |

---

### 5. `secrets.token_hex(n)`

Generates **n random bytes** and returns them as a hexadecimal string.

```python
secrets.token_hex(16)
```

**Example output:**
```
3fa1d76ce3c4f2a67d1f94e55bd02c91
```

| Use case |
|----------|
| API Keys |
| Tokens |
| IDs |
| Secret values |

---

### 6. `secrets.token_urlsafe(n)`

Generates a secure random string that is safe to use in URLs.

```python
secrets.token_urlsafe(16)
```

| Use case |
|----------|
| Password reset links |
| Session tokens |
| Authentication URLs |

---

### 7. `secrets.compare_digest(a, b)`

Compares two strings or bytes **in constant time** to prevent **timing attacks**.

```python
import secrets

stored_token = "abc123"
user_token = "abc123"

if secrets.compare_digest(stored_token, user_token):
    print("Valid token")
else:
    print("Invalid token")
```

| Why it matters | Description |
|----------------|-------------|
| Timing attack prevention | Regular `==` comparison short-circuits and leaks timing info |
| Constant time | Always takes the same time regardless of how many characters match |
| Security critical | Must be used when comparing passwords, tokens, or HMACs |

> **Always use `compare_digest()` instead of `==` when comparing secrets.**

---

## Password Generation

For custom passwords with full control over character sets:

```python
import string
import secrets

alphabet = (
    string.ascii_letters +
    string.digits +
    string.punctuation
)

password = "".join(
    secrets.choice(alphabet)
    for _ in range(16)
)
```

| Advantage | Description |
|-----------|-------------|
| Customization | You control the allowed characters |
| Policy compliance | Can satisfy password policies |
| Flexibility | More flexible than `token_hex()` |

---

## Function Comparison

| Function | Output Type | Best For |
|----------|-------------|----------|
| `choice()` | Single character | Custom passwords |
| `randbelow(n)` | Integer `0 <= x < n` | Random indices, ranges |
| `randbits(k)` | Integer with `k` bits | Cryptographic key sizes |
| `token_bytes(n)` | `bytes` object | Raw binary data, encryption keys |
| `token_hex(n)` | Hex string (`0-9`, `a-f`) | API keys, tokens, IDs |
| `token_urlsafe(n)` | URL-safe base64 string | Password reset links, session tokens |
| `compare_digest(a, b)` | `bool` | Secure token/password comparison |

---

## Key Takeaways

- `random` → Non-security tasks only.
- `secrets` → Security-sensitive tasks only.
- **Never** generate passwords with `random`.
- `choice()` is ideal for **custom passwords**.
- `randbits()` is ideal for **cryptographic integers**.
- `token_bytes()` is ideal for **raw binary data**.
- `token_hex()` is ideal for **secure tokens**.
- `token_urlsafe()` is ideal for **URL-safe tokens**.
- `compare_digest()` is essential for **secure comparison** (prevents timing attacks).
- `randbelow()` returns secure random **integers**.
- More entropy = harder to predict = stronger security.
